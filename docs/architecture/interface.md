# Pi control plane and optional dashboard

Control-plane implementation: `extensions/p2o/**`, `src/interface/**`, `tests/interface/**`, this document. This fixture/assessment MODE follow-up edits only `src/interface/**`, `tests/interface/**` and `docs/architecture/interface.md`; no extension, other module, root packaging or global Pi configuration edits.

## Entry point and seam

`extensions/p2o/index.ts` default-exports the Pi extension factory and also exports `registerP2O(pi, { backendFactory })` for tests/integration. The factory registers the 14 `p2o_*` tools plus the single human `/p2o` command, one `session_start` status line and one idempotent `session_shutdown` cleanup handler. It starts no process, socket, timer, manifest or dashboard at load time.

| Tool | Purpose |
|---|---|
| `p2o_start` | `preflight` → supervisor `admitRun` → prompt `start`. Launch-only; returns `resultAcceptance: not-evaluated`, `findingVerification: not-evaluated`, and `observed.attestation: unavailable`. |
| `p2o_status` | Read-only projection of run/task/attempt process state, packet acceptance, finding state, coverage, execution failures, requested-versus-observed runtime receipts and a comparison verdict. |
| `p2o_stop` | Supervisor `cancel` plus verified termination (draining state, non-terminal attempts, outstanding workspace leases). Unverified termination throws `STOP_UNVERIFIED`; closure/fences are retained. |
| `p2o_resume` | Identity/expiry/deadline re-checks, `recover` (no launch, no kill, no conversation replay), then `start`. Terminal runs are refused. |
| `p2o_preflight` / `p2o_doctor` | Read-only admission/readiness report. `doctor` uses `ControlBackend.doctor` when implemented. Passing is never permission; both are re-run at dispatch. |
| `p2o_tasks`, `p2o_evidence` | Paginated durable metadata. Evidence is metadata only: no artifact bytes, locators, tokens or raw logs. |
| `p2o_report` | Vault-backed qualified report (JSON/Markdown) from the trusted composition; fails closed with `INTEGRATION_REQUIRED` when the vault-backed renderer is absent. |
| `p2o_events` | Paginated durable receipts with cursor/gap semantics. Free text appears only when a trusted collector marks the payload redacted. |
| `p2o_dashboard` | Explicit opt-in (`enabled: true` + `runId`) loopback read-only dashboard; `action: close` stops the server only. |

The human entrypoint is the single `/p2o` command (`src/interface/argv.ts`, `command.ts`): shell-free flags/verbs, no JSON on the command line, and no target workflow call before an interactive `ctx.ui.confirm`. `p2o_plan` approval is human-command-only — the tool path is refused with `APPROVAL_HUMAN_ONLY`. Tool arguments, command dispatch inputs and post-`tool_call` mutations are re-validated with compiled TypeBox (`typebox/schema`) plus a plain-JSON/accessor/`__proto__` guard. Failures are reported by throwing, never by a fabricated success envelope. Tool output is bounded at 48KiB and record pages at 100 items.
The backend-factory context carries one opaque extra: `planAuthor`, the host session's model-author seam for the planning step. The extension binds the current Pi session model through it; the interface never interprets it, never treats it as confirmation, and a composition that ignores it leaves `plan` failing closed with `ENTRY_PLAN_AUTHOR_REQUIRED`.


Prompt metadata never implies permission: every tool guideline states that calling the tool, possessing targets, or passing preflight does not establish authorization, and that process completion, packet acceptance, verification and coverage stay separate.

## Trusted composition (exact integration)

`src/interface/index.ts` exports `ControlBackend`, `InterfaceController`, `createSupervisorBackend`, `createOrchestratorPort`, `createDefaultBackend`, `assertBackend`, the schemas and the projection helpers. Imports use `.js` specifiers.

`createDefaultBackend` uses the bundled first-use composition: with no override, `/p2o` runs UI onboarding and synthesizes the owner configuration. An optional `P2O_CONTROL_MODULE` override must be an absolute, canonical, owner-controlled `.mjs`/`.js` file (not a symlink, not group/world-writable, same UID) exporting `createP2OBackend({ cwd })` that returns a complete backend; an invalid or unsafe override fails closed with `INTEGRATION_REQUIRED`. There is no host-tool fallback and no ambient provider/credential default.

The operator composition supplies what the interface must not invent:

1. `openStore({ path, clock })` (`src/store`) for the durable run/task/attempt/evidence/event state.
2. `createSupervisor({ store, authority, controlRoot, workspaceRoot, runtimes, results?, events?, clock?, automatic?, ... })` (`src/orchestrator`) — `authority` is the owner-verifying boundary and must approve the exact canonical proposal digest. `controlRoot` is the supervisor's private controller directory; `workspaceRoot` is the approved canonical root of per-task workspaces and is required for managed admission. Both must be pre-created owner-only (0700) absolute canonical directories, and must stay disjoint from each other and from every runtime adapter's own `controlRoot` (`src/runtime/managed.ts` rejects an overlapping workspace/controller pair as well).
3. `createOrchestratorPort(supervisor, { perTargetConcurrency?, runtimes?, verifyCancellation? })` (`src/interface/orchestrator-port.ts`) mapping the settled `SupervisorApi` onto the interface port. The mapping is type-checked against `src/orchestrator/types.ts`:
   - `admitRun({ manifest, mode })` → `supervisor.admitRun({ manifest, mode: 'managed', perTargetConcurrency })` with an exact entry for every approved target: `min(option, budgets.maxConcurrency)`, default option 1. The option must be a positive safe integer; a rounded or widened grant throws `INTEGRATION_INVALID` instead of being coerced.
   - `preflight({ manifest })` returns adapter readiness when `runtimes` (the registered `{ kind, capabilities }` table) is supplied: an unregistered requested adapter is `RUNTIME_NOT_REGISTERED` and a non-owning adapter is `UNMANAGED_RUNTIME_REJECTED`. Without `runtimes` it reports readiness as explicitly unverified rather than assumed; it never mutates state.
   - `start` → `supervisor.start(runId)` and returns immediately; the control plane never waits for settlement.
   - `cancel` → `supervisor.cancel(runId)`; `terminationVerified` is derived only from `draining === false`, zero non-terminal attempts and zero `outstandingLeases`. `verifyCancellation` may inject an owner-side attestation.
   - `recover`/`snapshot`/`dispose` pass through.
   - The interface's own durable `run.admitted` receipt keeps the fixture/assessment label (`mode`, `manifestDigest`). The supervisor independently records ownership `mode: 'managed'` and `safetyMode` in `orchestrator.run-admitted`; neither event grants authority.
4. A vault-backed `render(runId, format)` using `src/reporting` + the supervisor's `EvidenceVault`. Before it is wired, `p2o_report` fails closed and preflight/doctor report a blocking `INTEGRATION_REQUIRED` issue — readiness is never a passing warning.
5. `createSupervisorBackend({ store, supervisor, render?, now?, perTargetConcurrency?, closeStore? })` returns the `ControlBackend` consumed by the Pi entry point.

**Seam for the application/package owners (`src/application`, root packaging).** The application composition owns store opening, authority, runtime adapters and supervisor tunables; the public interface entry is `src/interface/index.js` (`.js` specifiers, NodeNext ESM). The minimum construction contract is: open the store; construct runtime adapters with the supervisor's `runtimeHooks()` before dispatch; build the supervisor with validated `controlRoot`/`workspaceRoot`; then `createSupervisorBackend({ store, supervisor: createOrchestratorPort(supervisor, { perTargetConcurrency, runtimes }), render, closeStore })`, exported as `createP2OBackend({ cwd })` from the module named by `P2O_CONTROL_MODULE`. Applications with approved task plans can supply a composition-specific `SupervisorPort` to admit those tasks before launch. The interface fabricates no authority, runtime, fixture or renderer; compiled-build/typecheck coverage for this import path is owned by packaging.

Additional guarantees enforced by the interface layer, independent of the supervisor: managed runs reject explicitly non-owning adapter names (`plan`, `preview`, `dry-run*`, `unmanaged*` → `UNMANAGED_RUNTIME_REJECTED`), while any other adapter name must still pass the supervisor's registered-runtime admission; duplicate writers are refused (`RUN_EXISTS`); authorization/validity/deadline are re-checked at dispatch and again after `recover`; `resume` additionally requires the supplied manifest to match the durable admitted run field-for-field on `authorization`, `budgets`, `requestedRuntime` and `allowedCapabilities` (`RUN_IDENTITY_MISMATCH` naming the first differing field) and requires the supplied fixture/assessment mode to match the durable `run.admitted` mode (`MODE_MISMATCH`) — resume cannot renegotiate scope, budget or runtime identity, and a change of `selection`/`runtime` on resume is rejected unless it equals the admitted identity; preflight reports missing trusted-composition pieces and unregistered/non-owning adapters as blocking issues, never as passing warnings; a preflight result is never reused as permission; `p2o_stop` deliberately ignores the parent abort signal so cancellation still reaches owned runtimes; `session_shutdown` aborts in-flight launches, stops owned runs and propagates `CLEANUP_UNVERIFIED` when termination cannot be attested.

## Fixture/assessment MODE boundary

The fixture guard in `src/interface/supervisor-backend.ts` follows the supervisor's lab/artifact safety classification, not the presence of a source input alone:

| Explicit mode | Eligible target identities (still subject to owner approval) |
|---|---|
| `fixture` | Declared `lab` fixtures and approved read-only `artifact` source inputs, including lab + source combinations. Every artifact requires its approved digest and revision. |
| `assessment` | Explicitly authorized assessment scope, including `web`/`service` targets and optional source artifacts. It is never selected automatically because a fixture has source inputs. |

Any `web` or `service` target makes fixture preflight/start/resume fail with `FIXTURE_SCOPE_INVALID`, even when listed in authorization, mixed with lab/source inputs, given a zero request budget, or addressed on loopback. The interface does not infer `lab` from a local URL. Allowing an artifact identity does not fetch or mount it, make arbitrary files read-only, grant capabilities/network access, or attest isolation: the trusted composition and broker must bind analysis to the approved read-only source snapshot. Schema/exclusion validation, independent owner admission, dispatch-time authorization/deadline checks and managed-runtime requirements remain mandatory.

**Application-owner API/tests:** no interface API shape change is required. `SupervisorPort.preflight({ manifest, mode })` and `admitRun({ manifest, mode })` already carry the requested safety label. The application must enforce its exact configured mode (`inert-local-fixture` → `fixture`; `authorized-assessment` → `assessment`) during preflight/doctor and direct start/resume dispatch, not infer it from target kinds or silently relabel an inert run. Direct `ControlBackend.resume` checks durable identity/mode and then calls `recover`/`start`; it does not call port preflight or admission. A configured application wrapper must therefore protect that direct resume path too. Application regressions belong to its owner: inert lab + source must start as `fixture`, assessment labeling must be refused there, and configured-mode mismatches in preflight/start/resume must cause no admission, recovery, launch or mode receipt.

The interface persists the chosen label in `run.admitted` and refuses resume mode changes (`MODE_MISMATCH`) independently of application configuration. Source digest/revision, scope, budgets, capabilities and runtime selection remain bound to the original durable identity; successful fixture preflight is never reusable authorization.

## Optional dashboard boundary

Explicit opt-in only, bound to `127.0.0.1` on a random port with a 32-byte per-instance bearer token. The token travels in the URL fragment (never a query, cookie, referrer, log, session entry or tool result) and is delivered to the user through `ctx.ui.notify`; opening from a headless context fails with `DASHBOARD_UI_REQUIRED`. All routes are GET-only: static shell plus `/api/status`, `/api/tasks`, `/api/evidence`, `/api/report`, `/api/events`, `/api/stream` (SSE). There is no action/mutation route.

Enforced: exact `Host`, same-origin `Origin`/`Sec-Fetch-Site`, no proxy headers, loopback socket; constant-time bearer comparison; CSP `default-src 'none'` with `script-src 'self'`, `frame-ancestors 'none'`, no `unsafe-*`; `no-store`; `X-Frame-Options: DENY`; no CORS; strict single-occurrence query allowlists; bounded bodies, headers, connections, SSE clients (8) and read concurrency; a slow SSE reader is disconnected instead of buffered. All rendered values go through `textContent` with `innerHTML` never used; the viewer caps events (200 lines / 64KiB) and streams frames under a fixed limit. The server starts only for an existing run, never launches work, and closing it does not stop an assessment.

## Reading and redaction

`src/interface/presentation.ts` projects every value before it reaches the model, a session entry or the dashboard: an explicit key denylist (tokens, secrets, credentials, lease/owner tokens, headers, environments, paths, `raw`/`payload`/`prompt`/`argv`/`logTail`) plus content redaction of private keys, bearer/basic credentials, `sk-`/`gh*`/JWT shapes, `key=value` secrets and URL userinfo. Values are read only through own data descriptors, so accessors, cycles and `toJSON` never execute; depth, node, array and byte limits apply. Dashboards and tools never expose worker ownership tokens, locators, credentials or artifact bytes.

Counts, `truncated`/`gap` flags and `failures` remain visible, and the status projection always states that process completion, packet acceptance and finding verification are independent and that coverage may be incomplete. A finished process/run is never presented as a comprehensive assessment.

## Residual integration items

1. **Application composition, exact mode and task admission (owner: application/parent, `src/application/**`).** The application owns store/authority/runtime/broker construction, its configured-mode enforcement and the full fixture workflow. It must admit approved tasks inside run admission, before launch: otherwise a zero-task run completes on the first pump and `backend.start` refuses an already-admitted run (`RUN_EXISTS`). The inspected application port already calls `admitApprovedTasks` from its `admitRun`; no post-start task-admission workaround is added here. The exact-mode API/test requirements above were communicated to the parent; application edits and E2E verification are outside this MODE slice.
2. The real `createSupervisor` seam is wired and verified (`node tests/interface/integration.mjs` → `INTEGRATION: PASS`, exit 0). This is a **required seam smoke test, not E2E**: it admits zero tasks by design and prints `scope: seam smoke test … not E2E`; the full fixture is owned by the application slice. The runner has no `SKIP`/`BLOCKED` success path — missing orchestrator, missing tooling, compile failure and scenario failure all exit 1 (verified with `P2O_TSC=/bin/false` and with a temp copy lacking `src/orchestrator/index.ts`).
3. The operator must supply the vault-backed `render` port. Without it `p2o_report` fails closed and preflight/doctor return a blocking `INTEGRATION_REQUIRED` issue, so readiness (and therefore `p2o_start`) fails closed rather than passing with a warning.
4. Dashboard CSP/rendering assumes no untrusted HTML is ever introduced into the viewer; new viewer features must keep `textContent`-only rendering and bounded buffers.
5. Build/package seam (owner: packaging): the operator `.mjs` named by `P2O_CONTROL_MODULE` can only import the compiled interface/application output, so `npm run build`/typecheck coverage of `src/interface/**` and `src/application/**` must stay wired by the packaging slice; the interface keeps `.js` specifiers for that path.
6. Node `v24.19.0` was used for verification; no execution receipt for another Node version is claimed.
