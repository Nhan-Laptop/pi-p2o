# Evidence, independent verification, and reporting

## Stable integration API

Owned paths: `src/evidence/**`, `src/reporting/**`, `tests/evidence/**`, `tests/reporting/**`, and this document. TypeScript ESM with `.js` imports; built-in Node APIs only (no package modifications, no Pi/runtime imports, no target code execution, no shell/eval/child processes). Imports use `.js` specifiers after compilation.

```ts
import {
```

- `openEvidenceVault({ root, artifactRoots, workerWriteRoots, knownSecrets?, limits?, clock? })` opens/creates a supervisor-only vault, verifies every existing integrity record and preserved artifact, and refuses a root inside any worker-writable root, a symlinked/non-canonical root, a second live writer, or a changed redaction policy. `limits`: `maxArtifactBytes`, `maxTotalBytes`, `maxReceipts`, `maxReceiptBytes`, `maxAgeMs`.
- `vault.issueCollector(grant)` returns an in-process `CollectorHandle` (a capability object; a role name, JSON field or receipt value is never authentication). Grant fields: `collectorId`, `role: 'collector' | 'verifier'`, `runId/taskId/attemptId`, `authorizationRef`, `environmentId`, `configurationDigest`, `scopeDigest`, `inputDigests`, `tool { name, version, implementationDigest }`, `toolGrantId`, `artifactRootIds`, `allowedKinds`, `allowedClassifications`, `originalEnvironment`, `modifications`, `validFrom`, `expiresAt`.
- `vault.admit(handle, submission)` / `vault.tryAdmit(...)` → `{ status: 'accepted', receipt, duplicate }` or `{ status: 'rejected', code, reason }`. Admission reads the actual file with no-follow identity checks, requires the caller-supplied digests/length to match, enforces kind/classification/root/environment/time/age/receipt/byte budgets, redacts before preservation (`artifacts/<sha256>.blob`, `records/<key>.json`, `0400`, owner-only, HMAC-sealed), and is idempotent by `(run, collector, idempotencyKey)`. A replay with different content under the same key is rejected.
- `vault.get/list/inspect/read/readCollected/close` re-verify record seal, artifact digest and byte length on every access. `read` returns the preserved (redacted) bytes; `inspect` exposes the admission record including the pre-redaction `originalDigest`/`originalBytes` (hashes only) and the collector/grant identities.
- `admitToolResult(vault, handle, { result, operationInput, artifactRootId, evidence })` authenticates a real tool-broker `ToolReceipt`: collected outcome, context/grant/tool/version/implementation identity, scope+configuration+input digests, observation window, the artifact listed by the receipt, and that worker-visible `data` equals the authenticated artifact bytes.
- `reviewHandoff(vault, packet, { authorization, task, attempt, reviewerId, now, upstreamEvidenceIds?, controllerReceipts? })` runs the shared H1–H6 gate plus vault-specific checks (byte-level receipt integrity, receipt↔attempt↔input↔authorization binding, producer ≠ reviewer, non-stale attempt) and returns an immutable `HandoffReview` with `decision.status` `accepted` or `returned-for-evidence` plus codes/questions. `controllerReceipts` may only add supervisor-minted runtime observations that are `kind: 'runtime'`, `trust: 'collector'` and listed by the durable attempt observation; anything else is a refusal, not evidence. Only `reviewHandoff` results can be reported (`assertHandoffReview`).
- `validateFinding(vault, finding, { reviewerId, now })` requires collector receipts bound to the exact claim (`metadata.claimDigest` or `test.invariant`), the full reproduction denominator, comparable original-policy negative controls, and — for `independently-validated` — a distinct authenticated verifier collector, a distinct attempt/environment, same input/configuration identity and a clean-environment runtime receipt. Static-only and unresolved states are retained verbatim.
- `replayFinding({ vault, broker, finding, recipe, replayId, verifierId, verifierTask, verifierAttempt, authorization, clock?, maxMs?, signal? })` accepts only fixed read-only HTTP checks (`LocalReplayRecipe`: baseline, negative control, probe with two exclusive predictions) against an owner-approved literal-loopback fixture, inside a bounded deadline, in a `CleanReplaySession` supplied by a trusted `CleanReplayBroker` (`environmentReceiptId`, `context`, `artifactRootId`, `httpTool`, `broker`, `close`). No script/command/module/eval interface exists; unknown recipe fields are rejected. Every observation is a verifier-collected receipt. `verifierId` is the verifier attempt's own durable per-attempt `attempt.ownerId` (orchestrator `producerIdentityFor`), which is distinct from the finding's `producerId`; the producing identity verifying its own finding is refused with `verifier-identity`. Outcomes: `accepted` (independently validated), `rejected` (safe observation → finding rejected), or `returned-for-evidence` (blocked/inconclusive/control failure/unconfirmed cleanup → finding kept `unresolved`).
- `createResultCollectorBridge({ vault, store, packets, grant, clock? })` returns the supervisor-side `ResultCollector` (structurally assignable to `src/orchestrator`'s interface, so no orchestrator import is required). Per `collect(handle)` it locates the staged packet only inside one approved vault artifact root, preserves the exact bytes in the vault (content-addressed `pkt-<sha256(attemptId:digest)>`, canonical/redacted JSON or text), imports every packet-referenced vault receipt with `store.putEvidence` (collector trust only; never overwrites conflicting store content), and hands the supervisor a packet parsed from the preserved bytes. It never calls `admitResult`: the supervisor's lease-fenced `store.admitResult` remains the only durable admission. `createWorkspacePacketSource({ root, rootId })` reads the conventional `<workspace>/handoff.packet.json`; any other staging convention is an owner-supplied `PacketArtifactSource`.
- `publishHandoffReviews({ vault, store, runId, reviewerId, now, controller, upstreamEvidenceIds? })` turns fenced store results into reviewer-authenticated `HandoffReview`s for reporting. Every result must resolve to a vault-preserved packet under the supervisor's observed-runtime normalization — `digestJson(normalizeAttestedPacket(preservedPacket, result.packet.observedRuntime)) === result.digest` — otherwise publication fails closed with `packet-not-preserved`. Controller runtime receipts are re-attested independently (`authenticateControllerReceipt`: collector trust, `kind: 'runtime'`, controller id/tool, listed by the durable `attempt.observedRuntime.receiptEvidenceIds`, and stored `controlRoot/receipts/<evidenceId>.json` bytes re-hashed and bound to the attempt request) and returned as `controllerReceipts`; a worker-trust, unlisted or tampered document is dropped, never promoted.
- `buildReport(options)` consumes only reviewer-authenticated reviews, a trusted run/tasks/attempts set, a planned coverage universe and accepted remediation/retest records; it re-validates findings, keeps returned/rejected records visible, verifies runtime receipts per attempt, and marks the assessment `incomplete` unless the declared plan is fully covered and no failure/return/unresolved state remains. Optional `controllerReceipts` + `controller` resolve supervisor-owned runtime observations only after `authenticateControllerReceipt` re-attests each one against its durable attempt; the evidence table records `attestation: 'vault' | 'controller'` so controller receipts are never presented as vault artifacts. `renderMarkdown` (plain-text escaped), `renderJson`, `renderSarif` (`2.1.0`) are deterministic; only reports built by `buildReport` render (`assertReport`).
- `CoverageLedger(vault, runId, items)` synthesizes an explicit `untested` record for every planned cell with no accepted decision, requires explicit supersession to replace a decision, and keeps superseded history. `reviewCoverage` refuses worker-asserted `tested`/`ruled-out`, missing/failed controls, and unreviewed `not-applicable`.
- `recordRemediation(vault, { remediationId, handoff, finding })` / `recordRetest(vault, { retestId, handoff, remediation })` derive H5 remediation and H6 retest records from accepted packets; exposure mitigation or unresolved repair cannot be relabelled root-cause closure, and deployed controls must test the repaired invariant.
- All H1–H6 gates, schemas, finding states, scope/runtime comparison and proof checks reuse `src/contracts/index.js`. Process exit, packet acceptance and finding verification remain independent; no path treats exit codes, artifact freshness, model agreement or prompt consensus as proof.

### Trust boundary

The supervisor opens a private evidence vault **outside all worker-writable roots**. Only it may issue collector capabilities and call admission. Workers can propose artifact references/packets, not mint trusted receipts. Admission verifies actual bounded bytes, tool/input/environment identities, collection windows and expected hashes, redacts before preservation, and binds receipts to private integrity records. Durable store `putEvidence` does not authenticate a collector or read artifact bytes: only admit vault-issued receipts there. The supervisor's own controller runtime observations are **not** vault collectors: `authenticateControllerReceipt` re-hashes the bounded document under `controlRoot/receipts/`, binds it to the durable attempt and its requested selection, and refuses `trust: 'worker'`, unlisted or tampered receipts before any review or report treats them as runtime evidence. Same-UID host workers can bypass directory permissions; this vault requires the runtime's independent worker isolation and does not pretend to supply it.

### Parent integration needs

1. Supply owner-approved shared run/task/attempt records and collector tool/version/implementation identities; hold collector handles and vault integrity material in the supervisor, never in worker RPC inputs or prompts.
2. Configure private vault root, explicit allowed artifact collection roots, worker-write roots, known-secret redaction, time/size limits, and a clock. Tool broker output is observation, not finding proof.
3. Broker `receiptSink` must route authenticated tool receipts/artifacts through a collector bridge. Broker tool-input digest differs from approved source artifact digests: preserve both. Never import receipts written by a worker directly into `DurableStore`.
4. Vault receipts are store-shaped: `store.putEvidence(receipt)` verifies run/task/attempt identity and keeps `provenance.trust: 'collector'`, so gate evaluation inside `store.admitResult` sees the same authenticated bytes this module verified. The application owner wires `createSupervisor({ ..., results: createResultCollectorBridge(...) })` so the worker's packet is preserved before admission, and `store.admitResult` stays the only fenced packet admission (`packet-not-preserved` refuses anything the bridge did not preserve). Runtime observations are controller receipts, not vault artifacts: pass `publishHandoffReviews(...).controllerReceipts` plus the `controller` policy into `buildReport` so they are re-attested, never imported as vault evidence and never promoted from `trust: 'worker'`. Verification uses a **distinct** verifier identity/attempt and fresh environment.
5. A replay provider must offer a qualified clean environment, explicit verifier grant and fixed named checks through the tool broker. No worker-supplied shell, script, Node module, command or arbitrary callback execution is supported. Static-only and inconclusive outcomes are retained; missing prerequisites return a bounded question.
6. Reporting consumes only reviewer-accepted packets, vault-authenticated receipts, checked finding/coverage records, accepted remediation and retest records. Supply the planned surface/actor/question universe so gaps become explicit `untested` entries. A completed process/run is not comprehensive coverage.
7. Root ESM/package/test integration remains with the parent. Owned tests have a standalone local runner using already provisioned TypeScript/Node types; no install step. `tests/evidence/fixtures.ts` reuses `tests/contracts/fixtures.ts` and mutates only freshly-created copies, so shared-fixture shape changes remain the integration owner's contract to keep stable.

## Residual boundaries

- Same-UID host workers can bypass directory permissions. The vault is a supervisor-side trust boundary, not a sandbox; it requires the runtime's independent worker isolation and does not replace it.
- Node filesystem checks are not openat2/kernel-level guarantees against hostile same-UID races, NFS or a privileged attacker; evidence, hashes, manifests and the vault must be access-protected separately.
- Redaction is defense in depth over textual artifacts and does not license exporting an arbitrary sensitive checkout; unsupported media, binary data and pre-existing leaks outside the known-secret policy are not covered.
- Replay covers only fixed read-only HTTP checks on an approved literal-loopback fixture through a broker the supervisor must actually qualify. It is not a general exploit verifier, does not execute worker scripts, and does not attest that a broker's container/VM isolation is sound.
- The `CleanReplayBroker`, credential provider, authorization minting, policy engine, sandbox and durable store remain the parent's responsibility. This module authenticates what it is handed and refuses to infer permission from a locator, a role name or prior success.
- The result-collector bridge and `publishHandoffReviews` verify bytes inside the supervisor trust domain (vault records, SQLite evidence rows, controller documents under `controlRoot`). They do not stop an actor who already has supervisor-level write access to all three and can rewrite them consistently; worker-writable roots remain the boundary that matters.
- No external target traffic, scans, container/VM execution, model-provider attestation or security audit was performed while implementing or testing these modules.
